# 1. 项目目标与定位

## 1.1 项目定位

E-Commerce Agent 是一个基于 Python 后端技术和大语言模型技术构建的 AI 电商应用项目。

项目以真实电商业务为基础，将传统业务系统与 AI Agent 能力结合，构建一个具备商品查询、订单管理、售后处理、知识库问答和业务工具调用能力的应用。

项目主要面向：

- Python 后端开发岗位；
- AI 应用开发岗位；
- 大语言模型应用开发岗位；
- Agent 应用开发岗位。

本项目既是工程实践作品，也是系统性的技术学习项目。

## 1.2 项目目标

项目最终需要具备以下能力：

1. 构建完整的 Python 后端工程基础设施。
2. 实现用户认证和基础权限控制。
3. 实现商品、SKU、库存等电商核心业务。
4. 实现订单、支付和售后完整业务流程。
5. 实现基于 RAG 的业务知识库。
6. 实现基于 LangGraph 的 AI Agent。
7. 让 Agent 通过受控工具调用真实电商业务。
8. 构建 React 管理后台和用户交互界面。
9. 完成自动化测试、系统集成和生产部署。
10. 形成可运行、可测试、可演示、可维护的完整项目。

## 1.3 项目验收目标

项目完成后，至少应当能够演示：

- 用户注册、登录和身份认证；
- 商品分类、商品、SKU 和库存管理；
- 创建订单、查询订单和取消订单；
- 模拟支付及支付宝沙箱支付流程；
- 退款、退货退款和简化换货；
- 上传业务文档并建立知识库；
- 基于知识库回答商品和售后政策问题；
- Agent 查询商品、库存、订单；
- Agent 通过受控工具执行允许的业务操作；
- 高风险操作具备确认机制；
- 前端与后端完整联调；
- 通过 Docker Compose 部署并从公网访问。

# 8. 最终验收标准

## 8.1 后端验收

- 所有核心 API 可以正常运行；
- 数据库迁移完整；
- 核心业务流程正确；
- 权限检查有效；
- 关键并发场景有保护；
- 异常处理统一；
- 自动化测试通过；
- Ruff 检查通过；
- Mypy 检查通过。

## 8.2 AI 验收

- RAG 能正确解析和检索业务文档；
- 检索结果能够提供来源；
- 文档权限得到执行；
- Agent 能正确识别用户意图；
- Agent 能选择正确工具；
- Tool 参数经过校验；
- Tool 通过 Service 执行业务；
- 高风险操作需要确认；
- Agent 无权越过后端权限边界；
- 安全测试和效果评测有明确结果。

## 8.3 前端验收

- 登录注册正常；
- 管理页面正常；
- 商品和库存操作正常；
- 订单和售后页面正常；
- 知识库管理正常；
- Agent 对话正常；
- 错误和加载状态明确。

## 8.4 部署验收

- Docker Compose 能启动生产服务；
- Nginx 能正确代理 API；
- HTTPS 正常；
- 环境变量和密钥安全；
- 数据持久化；
- 日志可查看；
- 备份和恢复方案可执行；
- 公网可以访问系统。

## 8.5 项目交付验收

最终需要形成：

- 可运行源码；
- 数据库迁移；
- 自动化测试；
- 项目架构文档；
- 业务设计文档；
- AI 设计文档；
- 部署文档；
- 学习文档；
- 项目演示材料；
- 面试讲解材料。
