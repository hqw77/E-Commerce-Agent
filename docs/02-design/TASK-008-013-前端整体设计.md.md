# 一、设计目标

## 1.1 项目目标

基于已经完成的 TASK-001～007 后端和 AI Agent 系统，开发一个完整的 React 管理后台。

前端需要把现有后端能力以可视化方式呈现出来，使用户能够：

1. 登录和管理自己的账号。
2. 管理商品、SKU 和库存。
3. 查看订单、支付和售后信息。
4. 上传和管理 RAG 知识库文档。
5. 与 AI Agent 进行自然语言对话。
6. 通过 AI Agent 查询真实电商业务。
7. 对订单取消、售后申请等高风险操作进行确认。

最终交付的是一个能够真实连接后端、可以完整演示业务流程的 AI 电商管理应用。

## 1.2 设计原则

### 原则一：前端不重复实现业务规则

所有业务规则以现有后端 Service 为准。

例如：

- 订单金额由后端计算。
- 库存数量由后端管理。
- 订单取消资格由 OrderService 判断。
- 售后资格由 AfterSaleService 判断。
- 用户权限由后端验证。
- Agent Tool 的调用权限由后端 Registry 和 Executor 控制。

前端负责展示数据、收集参数、调用 API 和反馈结果。

### 原则二：以现有后端 API 为唯一接口依据

开发前检查现有 API 路由、Pydantic Schema 和 Service。

禁止：

- 自行猜测 API 路径。
- 自行发明请求字段。
- 自行发明响应字段。
- 为了适配前端擅自修改已验收业务规则。
- 通过前端绕过后端 Service。

### 原则三：前端保持简单

本项目重点是 Python 后端和 AI Agent 开发。

前端不追求复杂的工程化架构，不引入不必要的依赖，不实现复杂动画。

优先保证：

- 代码容易理解。
- 目录清晰。
- API 调用统一。
- 业务页面职责明确。
- TypeScript 类型完整。
- 方便后续维护。

### 原则四：Agent 页面是核心展示入口

整个前端最重要的页面是 AI Agent 对话页面。

商品、库存、订单、售后和知识库页面体现后台管理能力。

Agent 页面体现项目的 AI 应用开发能力，必须能够真实展示 Agent 查询业务、检索知识和执行确认操作的过程。

# 二、前端技术架构

# 三、TASK-008：前端基础工程

## 3.1 工程初始化

创建独立的 frontend 目录。

使用 React + TypeScript + Vite。

完成：

- 项目初始化。
- 依赖安装。
- Ant Design 配置。
- 中文语言环境。
- 路由初始化。
- 全局样式。
- TypeScript 配置。
- 环境变量配置。
- 开发服务器配置。
- 生产构建配置。

## 3.2 环境变量

提供：

```env
VITE_API_BASE_URL=http://localhost:8000/api/v1
```

具体地址根据现有后端配置调整。

前端环境变量只能存放公开配置，不能存放：

- DeepSeek API Key。
- MySQL 密码。
- Redis 密码。
- JWT Secret。
- 支付宝私钥。

## 3.3 统一请求客户端

创建：

```text
src/api/client.ts
```

统一管理：

- Axios Base URL。
- 请求超时。
- Authorization Header。
- 请求拦截器。
- 响应拦截器。
- 统一错误处理。
- 401 处理。
- Token Refresh 协调。

业务 API 不允许各自创建独立 Axios 实例。

## 3.4 数据请求管理

使用 TanStack Query 或简单封装实现：

- 加载状态。
- 错误状态。
- 数据缓存。
- 页面数据刷新。
- 新增、修改、删除后的缓存失效。

不需要引入复杂的数据流管理框架。

## 3.5 验收标准

- 项目正常启动。
- TypeScript 检查通过。
- Vite 构建通过。
- Ant Design 正常显示。
- 路由能够正常工作。
- API Base URL 能够配置。

## 4.2 注册页面

- 密码输入。
- 确认密码。
- 表单校验。
- 注册结果提示。

以实际注册 API 为准。

如果后端没有提供某项能力，不得伪造接口。

## 4.3 认证流程

```text
用户提交登录
    │
    ▼
POST Login API
    │
    ▼
后端验证账号密码
    │
    ▼
返回实际认证结果
    │
    ▼
前端建立登录状态
    │
    ▼
进入后台
```

Refresh 流程：

```text
业务 API 请求
    │
    ▼
返回 401
    │
    ▼
检查是否属于可刷新场景
    │
    ▼
执行 Refresh API
    │
    ▼
成功
    │
    ├── 更新认证状态
    └── 原请求最多重试一次
    │
    ▼
失败
    │
    ▼
清理认证状态
    │
    ▼
跳转登录页面
```

必须考虑 TASK-002 的 Refresh Token Rotation。

并发请求不能重复刷新同一个 Refresh Token。

采用统一刷新锁或共享 Promise 协调刷新过程。

Token 存储方式必须结合现有后端实际返回机制决定。

如果后端返回 JSON Token，不能假设其已经具备 HttpOnly Cookie 保护。

应在实现报告中说明存储方案及其 XSS、CSRF 风险。

# 八、TASK-013：AI Agent 对话页面

## 8.1 页面定位

Agent 是整个项目最重要的演示入口。

页面需要体现：

- 普通对话。
- RAG 知识检索。
- 商品查询。
- 库存查询。
- 订单查询。
- 售后查询。
- 订单取消确认。
- 售后申请确认。

前端只负责展示 Agent 的真实处理结果，不重新实现 Agent 的判断逻辑。

## 8.2 页面布局

```text
┌─────────────────────────────────────────────┐
│                 AI Agent                    │
├──────────────┬──────────────────────────────┤
│              │                              │
│  当前会话    │       对话消息区域            │
│              │                              │
│  新建会话    │  用户消息                    │
│              │                              │
│              │  AI 回复                     │
│              │                              │
│              │  Tool 结果                   │
│              │                              │
│              │  RAG 来源                    │
│              │                              │
│              ├──────────────────────────────┤
│              │                              │
│              │       消息输入框              │
│              │                              │
└──────────────┴──────────────────────────────┘
```

如果后端没有会话列表 API，第一版不实现持久化会话列表。

允许实现当前会话和新建会话功能。

## 8.3 普通对话流程

```text
用户输入问题
    │
    ▼
前端 POST Agent Chat API
    │
    ▼
后端 AgentRuntime
    │
    ▼
LangGraph 执行
    │
    ▼
返回 AgentResponse
    │
    ▼
前端展示 AI 回复
```

前端需要：

- 输入框。
- 发送按钮。
- Enter 发送。
- Shift + Enter 换行。
- 请求加载状态。
- 防止重复提交。
- 错误反馈。
- 会话 ID 延续。

当前使用非流式 API，不开发 SSE 或 WebSocket。

## 8.4 RAG 来源展示

Agent 返回 sources 时展示：

- 文档名称。
- 文档来源。
- 相关片段（如果返回）。

来源必须直接使用后端返回的 sources。

前端不得从 AI 回复正文中解析来源并构造可信来源。

## 8.5 Tool 调用结果展示

根据真实 Agent API 返回结构，区分：

- 商品查询。
- SKU 查询。
- 库存查询。
- 订单查询。
- 售后查询。

展示用户能够理解的结果。

不得向用户展示：

- Python 内部对象。
- 数据库自增 ID。
- Redis Key。
- 内部异常堆栈。
- 其他敏感字段。

## 8.6 Prepare / Confirm 确认流程

这是 TASK-013 的核心设计。

### Prepare 阶段

Agent 调用：

- prepare_cancel_order；
- prepare_create_after_sales。

后端返回 pending_action。

前端展示确认卡片。

卡片至少展示：

- 操作类型。
- 业务编号。
- 操作影响。
- 操作摘要。
- 过期时间（如果提供）。
- 确认按钮。
- 放弃按钮。

示例：

```text
┌────────────────────────────────────┐
│        请确认订单取消操作          │
│                                    │
│ 订单编号：ORD2026XXXX              │
│ 操作：取消待支付订单               │
│                                    │
│ 取消后订单将变为 CANCELLED         │
│ 对应预留库存将按业务规则释放       │
│                                    │
│       [确认取消]  [暂不操作]       │
└────────────────────────────────────┘
```

### Confirm 阶段

调用现有接口：

```http
POST /api/v1/agent/actions/{confirmation_id}/confirm
```

请求体严格遵循 TASK-007 Schema。

当前设计要求：

```json
{
  "conversation_id": "uuid",
  "nonce": "opaque-nonce"
}
```

不能额外提交：

- user_id；
- order_no；
- SKU；
- amount；
- after_sales_type；
- 其他业务参数。

这些参数已经绑定在后端 Redis confirmation 中。

### 确认交互流程

```text
Agent 返回 pending_action
        │
        ▼
前端展示确认卡片
        │
        ▼
用户点击确认
        │
        ▼
按钮进入 Loading
        │
        ▼
调用 Confirm API
        │
        ▼
后端原子消费确认凭证
        │
        ▼
Service 执行业务操作
        │
        ▼
返回实际结果
        │
        ▼
前端展示执行结果
```

### 安全要求

1. 确认按钮必须防止重复点击。
2. 未收到后端成功结果前不得显示成功。
3. 过期凭证提示重新发起操作。
4. 已消费凭证不能再次确认。
5. 用户放弃操作只表示前端不再主动确认，不代表后端已撤销 Redis 凭证。
6. 前端不能修改 Prepare 阶段已经绑定的业务参数。
7. 不在浏览器中自行执行订单取消或售后申请。

### 售后结果展示

售后申请成功后，应展示真实返回状态：

PENDING_REVIEW

不能显示：

- 售后已审核通过。
- 已完成退款。

因为提交申请与审核、退款是不同阶段。

## 8.7 错误处理

处理：

- Agent 超时。
- Agent 服务不可用。
- Tool 参数错误。
- 业务权限不足。
- 订单状态不允许操作。
- Confirm 过期。
- Confirm 已消费。
- 网络错误。
- Redis 不可用。

使用用户能够理解的中文提示。

不暴露内部异常详情。

## 8.8 验收标准

- 普通对话正常。
- 会话 ID 能够延续。
- RAG 来源正确。
- Tool 结果正确。
- pending_action 正常展示。
- Confirm API 正常调用。
- 重复点击不会重复执行。
- 业务执行结果真实展示。
- 非流式交互正常。

# 十一、前端安全设计

## 11.1 身份认证

- 用户身份由后端认证。
- 前端不能自行指定 user_id。
- 不允许客户端伪造管理员权限。
- Refresh Token 必须遵守后端 Rotation 机制。
- 认证失败必须清理客户端登录状态。

## 11.2 敏感信息

禁止前端保存：

- DeepSeek API Key。
- 数据库密码。
- Redis 密码。
- JWT Secret。
- 支付宝私钥。

禁止将 Access Token、Refresh Token 和确认凭证写入普通业务日志。

## 11.3 Agent 安全

- 前端只负责展示 Agent 返回的工具信息。
- 不允许前端自行决定工具是否有权执行。
- Confirm 参数必须严格匹配后端。
- 不允许修改已经 Prepare 的业务参数。
- 不允许通过前端跳过确认流程。
- 最终权限由后端保证。

## 11.4 XSS 和输入安全

- 使用 React 默认文本转义。
- 避免不必要的 dangerouslySetInnerHTML。
- 如果展示 Markdown，使用安全配置的渲染组件。
- 不直接执行模型返回的 HTML 或脚本。
- 上传文件限制由前后端共同实施，后端校验为最终依据。
