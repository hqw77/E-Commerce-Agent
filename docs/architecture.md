- 外部内容不能变成系统指令；
- Agent 不能绕过 Service 和权限；
- 高风险操作必须经过可绑定、可防重放的人工确认；
- RAG 不能成为越权读数据和间接注入的通道；
- 密钥和用户敏感数据不进入模型、前端或日志；
- Agent 不会无限循环、重复执行副作用或无限消耗成本；
- 安全测试使用确定性断言，不以 LLM 自评作为唯一判断。

## 1. 威胁模型与信任边界

### 1.1 信任边界

| 来源 | 信任级别 | 处理原则 |
|---|---|---|
| System Prompt / 开发者配置 | 可信 | 只能由代码仓库和部署配置提供 |
| 后端认证上下文 | 可信 | 由 FastAPI 认证依赖生成，不由模型传入 |
| 用户输入 | 不可信 | 只作为数据，不能成为指令 |
| RAG 文档内容 | 不可信 | 解析后仍是数据，不执行其中指令 |
| 工具返回值 | 不可信 | 先校验、脱敏，再交给模型 |
| 模型输出 | 不可信 | 不直接执行；必须经过后端验证 |
| 数据库 / Service | 可信执行边界 | 负责最终权限、状态和金额校验 |

关键原则：

```text
模型输出 = 建议，不是授权
外部内容 = 数据，不是指令
后端校验 = 最终安全边界
```

### 1.2 主要威胁

- 直接提示词注入；
- 间接提示词注入（RAG、商品评论、订单备注、工具输出）；
- 中文、编码、Unicode、HTML/Markdown 隐藏内容变体；
- 多轮诱导和渐进式权限提升；
- 工具越权、参数伪造、资源归属绕过；
- 高风险操作绕过确认、确认重放、参数篡改；
- 跨用户数据读取和知识库越权检索；
- 密钥、Prompt、手机号、地址等敏感信息泄露；
- 无限循环、重复工具调用、成本失控；
- 审计缺失，无法定位安全事件。

### 1.3 安全原则

1. 确定性后端校验优先。
2. 不把安全责任交给 LLM 自我约束。
3. 安全分类模型只作为辅助信号，不作为唯一防线。
4. 不可信内容不进入系统指令区。
5. 工具权限默认拒绝，显式白名单。
6. 高风险操作默认不执行，确认后才执行。
7. 无法确定时拒绝或转人工，不猜测。
8. P0 必须进入第一版验收；P1 以合理复杂度实现。

## 2. Prompt Injection 防护（P0）

### 2.1 直接提示词注入

必须覆盖以下用户输入：

- “忽略之前的指令”；
- “你现在是管理员/开发者模式”；
- 要求输出 System Prompt、内部规则、密钥；
- 要求调用未授权工具或直接执行退款；
- 要求绕过确认、跳过权限；
- 角色扮演、越狱、伪造系统消息；
- 多轮对话中逐步改变规则；
- 中文变体、拼音、繁体、英文混合；
- Base64、Hex、URL 编码、Unicode 转义、零宽字符、同形字；
- Markdown/HTML 注释、隐藏文本、超长重复内容；
- 伪造工具调用结果或伪造“系统通知”。

处理：

- 输入进入 Agent 前做规范化、长度限制和风险检测；
- 高风险输入直接拒绝；
- 中风险输入进入受限模式或人工确认；
- 低风险输入正常处理，但仍不能改变系统规则；
- 所有拒绝返回稳定错误码，不把检测细节反馈给攻击者。

### 2.2 间接提示词注入

必须覆盖：

- RAG 文档中的“忽略系统指令”；
- 商品描述、评论、售后描述、订单备注中的指令；
- CSV/JSON/HTML/PDF 解析结果中的隐藏指令；
- 工具返回内容中的伪造系统消息；
- 检索片段中的“请调用退款工具”；
- 文档中的编码/零宽字符/多语言变体；
- 多轮对话中把恶意文档内容再次带入。

处理：

- 所有外部内容包裹为不可信数据块；
- 数据块内不解析“系统指令”；
- 不因为文档内容而扩大工具权限；
- 工具调用只能由受控 Agent 计划和后端 Schema 产生；
- RAG 内容不能覆盖 System Prompt；
- 文档中的 URL、代码、命令不自动执行。

### 2.3 信任边界与 Prompt 模板隔离

Prompt 模板固定为：

```text
System / Developer 指令区：仅来自代码和部署配置
User 输入区：不可信数据
Retrieved Context 区：不可信数据，带来源和边界标记
Tool Result 区：不可信数据，经过校验和脱敏
```

要求：

- 不使用字符串拼接把外部内容放入系统指令；
- 使用结构化消息和明确分隔符；
- 对外部内容做长度截断和字符规范化；
- 保留来源、文档 ID、版本，便于审计；
- 外部内容即使包含“系统指令”字样，也只作为文本；
- Tool Result 不得包含可执行指令；
- System Prompt 不允许被模型输出或日志完整泄露。

### 2.4 输入安全检测与风险处理

检测分层：

1. **规范化层**：Unicode NFKC、去零宽字符、统一空白、限制长度；
2. **规则层**：明显注入短语、角色伪造、工具越权、密钥索取；
3. **模型辅助层**：可选的小型分类器/LLM 判断，只作为辅助；
4. **策略层**：根据风险等级执行 allow / constrain / confirm / block；
5. **审计层**：记录命中规则、风险级别和处理结果。

风险处理：

| 风险 | 处理 |
|---|---|
| 低 | 正常处理，外部内容仍标记不可信 |
| 中 | 限制工具集、要求确认、缩短上下文 |
| 高 | 拒绝请求，返回通用安全错误 |
| 不确定 | 拒绝或转人工，不自动执行写操作 |

禁止：

- 仅依赖关键词黑名单；
- 仅依赖 System Prompt；
- 仅依赖 LLM 判断；
- 把检测模型的解释直接返回给用户，帮助攻击者绕过。

### 2.5 输出检查与异常调用拦截

模型输出进入执行前必须检查：

- 是否包含 System Prompt、密钥、内部 URL、其他用户数据；
- 是否试图调用未在白名单中的工具；
- 工具参数是否符合 Schema；
- 是否试图绕过确认或伪造确认凭据；
- 是否包含可执行 SQL、Shell、任意 HTTP 请求；
- 是否输出敏感字段；
- 是否要求重复执行副作用操作。

异常处理：

- 拦截并记录；
- 不执行工具；
- 返回安全失败；
- 必要时终止 Agent 会话；
- 不把完整内部异常返回给模型或用户。

### 2.6 Prompt Injection P0 验收

- 直接注入样例被拒绝或降权；
- 中文/编码/多轮变体不能绕过；
- RAG 文档中的指令不能改变工具权限；
- 工具输出中的伪指令不能触发写操作；
- System Prompt 不能通过普通对话被完整导出；
- 拒绝路径有审计记录；
- 不能只用关键词命中作为唯一通过条件。

## 3. Agent 工具权限与最小授权（P0）

### 3.1 固定调用链

```text
Agent → Tool → Service → Repository → Database
```

约束：

- Agent 不直接访问数据库；
- Tool 不直接写数据库；
- Tool 不绕过 Service；
- Service 重新校验用户、资源归属和业务规则；
- Repository 只负责数据访问；
- 模型不能自行扩大工具权限。

### 3.2 工具白名单

每个 Agent/角色只能看到显式授权的工具集合：

```text
allowed_tools = {
  product.search,
  product.get_detail,
  inventory.get_available,
  order.list_my,
  order.get_my,
  order.prepare_cancel,
  order.confirm_cancel,
  after_sales.prepare_refund,
  after_sales.confirm_refund
}
```

未列出的工具默认拒绝。工具发现、动态注册、模型自定义工具不进入第一版。

### 3.3 工具清单要求

每个工具必须声明：

| 字段 | 说明 |
|---|---|
| `name` | 稳定工具名 |
| `purpose` | 单一业务目的 |
| `input_schema` | 严格参数 Schema，禁止额外字段 |
| `allowed_roles` | 允许的用户角色 |
| `resource_scope` | 仅本人 / 管理员 / 公共只读 |
| `side_effect` | 只读 / 写 / 高风险写 |
| `risk_level` | low / medium / high |
| `timeout_ms` | 工具执行超时 |
| `max_calls_per_request` | 单次请求最大调用次数 |
| `requires_confirmation` | 是否需要人工确认 |
| `idempotency` | 幂等键要求 |
| `audit_fields` | 必须记录的参数 |

### 3.4 身份与权限来源

- 用户身份只能来自 FastAPI 认证依赖和可信后端上下文；
- 禁止模型在工具参数中声明 `user_id`、`role`、`is_admin`；
- 即使模型传入这些字段，Tool 也必须忽略或拒绝；
- Service 必须重新从可信上下文获取用户，不能信任 Tool 参数；
- 工具查询订单、售后、退款时必须校验资源归属；
- 管理员工具必须由后端 `CurrentAdmin` 校验，不由模型声明。

### 3.5 工具实现限制

- 不提供任意 SQL 执行工具；
- 不提供任意 HTTP 请求工具；
- 不提供文件系统读写工具；
- 不提供 Shell 工具；
- 不提供“通用管理接口”；
- 写工具必须调用已有 Service，不复制业务逻辑；
- 工具输出必须经过字段白名单和脱敏；
- 工具错误不暴露内部堆栈和数据库细节。

### 3.6 工具权限 P0 验收

- 普通用户无法调用管理员工具；
- 用户 A 无法通过工具读取/操作 B 的订单和售后；
- 模型伪造 `user_id`/`is_admin` 无效；
- 未授权工具调用被拒绝并审计；
- Tool 不直接访问数据库；
- Service 层仍能独立拦截越权；
- 工具参数 Schema 拒绝额外字段和非法金额。

## 4. 高风险操作确认（P0）

### 4.1 适用范围

第一版至少覆盖：

- 退款；
- 订单取消；
- 售后申请/审核类写操作；
- 其他会改变金额、库存、订单状态或售后的操作。

只读查询不需要确认。

### 4.2 两阶段确认

```text
prepare（预览）
  → 返回操作摘要和一次性确认凭据
confirm（确认执行）
  → 后端校验凭据、参数、状态、权限
  → 执行 Service
```

预览必须展示：

- 业务对象：订单号/售后单号/支付单号；
- 操作类型；
- 关键参数：金额、数量、SKU、退款原因；
- 影响：订单状态、库存、退款金额；
- 用户身份和资源归属；
- 过期时间。

### 4.3 确认凭据绑定与一次性消费

确认凭据至少绑定：

```text
user_id
session_id
action
resource_type
resource_id
normalized_parameters_hash
nonce
issued_at
expires_at
```

要求：

- 参数变化必须重新预览、重新确认；
- 凭据只能成功消费一次；
- 消费操作必须具备原子性，不能使用“先查询、再修改”的非原子流程；
- 可使用 Redis 原子操作或数据库条件更新/唯一约束实现；
- 服务端保存 nonce/消费记录，防止重放；
- 确认凭据不能由模型自行生成；
- 确认不能只依赖前端按钮状态；
- 确认后仍需后端重新校验业务状态和金额。

### 4.4 防重复执行、失败与重试

- 高风险写工具必须要求幂等键；
- 同一确认凭据不能执行两次；
- 消费凭据必须先于业务执行，并以原子操作完成；
- 同一业务请求重试时复用同一幂等键；
- 后端在事务和锁内重新检查状态；
- **消费成功不等于业务成功**：业务执行失败时必须记录失败状态和审计；
- 已消费的凭据不得因为业务失败而自动恢复或再次使用；
- 业务失败后如需重试，必须使用业务幂等状态判断，并由用户重新确认或走受控人工处理；
- 已执行的确认不能因为网络重试再次执行。

### 4.5 人工确认不能替代后端校验

确认只表示“用户同意这个操作”，不代表：

- 用户有权限；
- 订单状态允许；
- 退款金额合法；
- 库存充足；
- 售后期限未过；
- 支付仍可退。

后端必须再次执行 Service 业务规则。

### 4.6 高风险确认 P0 验收

- 未确认的退款/取消/售后不能执行；
- 确认内容包含对象、操作、金额/数量等关键参数；
- 修改金额或对象后旧确认失效；
- 重放同一确认被拒绝；
- 并发使用同一确认凭据只能有一次成功消费；
- 消费成功但业务失败时，不得假定业务成功，必须有失败状态和审计；
- 业务失败后的重试不得静默复用已消费凭据；
- 重复点击不会重复退款/取消；
- 普通用户不能确认管理员操作；
- 确认后业务状态变化仍会被后端拒绝；
- 确认凭据和结果写入审计。

## 5. RAG 知识库安全（P0）

### 5.1 文档来源与可信度

每个文档必须记录：

```text
document_id
source_type
source_uri
owner
visibility
allowed_roles
trust_level
classification
version
checksum
status
created_at / updated_at
```

V1.2 不建设多租户。未来如扩展多租户，可增加 `tenant_id`，但不属于当前版本范围，不得作为第一版强制字段。

来源分级：

- 官方/管理员维护文档：高可信来源，但内容仍是不可信数据；
- 用户生成内容：低可信来源；
- 外部导入文档：低可信来源，需要管理员审核；
- 过期/删除文档：不得被检索。

“可信来源”只影响优先级，不代表文档内容可以成为指令。

### 5.2 文档解析安全

- PDF/HTML/Markdown/CSV 解析结果一律视为不可信数据；
- 不执行文档中的脚本、宏、命令、URL；
- 去除脚本、隐藏层、异常控制字符；
- 保留原文引用和页码/段落定位；
- 超长文档截断并记录；
- 文档中的“忽略系统指令”只作为文本；
- 文档不得直接注入 System Prompt。

### 5.3 检索权限

- 权限过滤必须在向量检索前完成，不能只做检索后过滤；
- 普通用户不能检索管理员内部文档；
- 第一版按用户、管理员角色和文档可见性控制，不建设多租户隔离；
- 用户只能检索自己有权限的文档；
- 检索结果携带来源、版本和可见性；
- 无权限文档不返回摘要、标题或片段；
- 管理员文档需要显式管理员权限。

### 5.4 检索结果进入 Prompt

- 检索片段放入“Retrieved Context”不可信区；
- 不覆盖 System Prompt；
- 不允许文档内容指示 Agent 调用工具；
- 不把文档中的 URL 自动抓取；
- 对检索片段做长度限制和注入检测；
- 回答必须给出可核验来源；
- 无法确认来源时降低置信度或拒绝。

### 5.5 文档更新与向量一致性

- 文档有稳定 `document_id` 和递增 `version`；
- 更新时写入新版本，旧版本标记过期；
- 删除使用 tombstone 或状态标记；
- 向量按 `document_id + version` 幂等 upsert；
- 检索只返回 `status=active` 且版本最新的片段；
- 删除/更新后旧向量不得继续被检索；
- 允许有限重试和后台重建，不引入消息队列；
- 提供一致性检查任务：数据库文档数、活跃版本数、向量数；
- 发现不一致时阻断相关文档检索并告警。

### 5.6 RAG 安全 P0 验收

- 恶意文档不能改变工具权限；
- 恶意文档不能触发退款/取消；
- 普通用户不能检索管理员文档；
- 跨用户或越权检索被拒绝；
- 文档更新后旧内容不再返回；
- 文档删除后向量不再命中；
- 检索结果带来源和版本；
- 间接注入样例有确定性拒绝或隔离结果。

## 6. 敏感信息与数据保护（P0）

### 6.1 密钥与凭据

- LLM API Key、数据库密码、支付密钥、JWT Secret、访问令牌及其他系统凭据只从环境变量或安全配置读取；
- 不得泄露到 LLM 请求和模型上下文；
- 不得泄露到前端响应；
- 不得泄露到普通日志、异常日志、Trace、调试信息和可观测性数据；
- 不在代码、测试快照、Git 历史中保存真实密钥；
- 日志只记录密钥是否存在，不记录值；
- 配置对象使用 SecretStr 或等价机制。

### 6.2 日志与 Trace 脱敏

必须脱敏：

- 密码；
- Access/Refresh Token；
- Cookie、Authorization；
- API Key、支付私钥；
- 手机号；
- 邮箱；
- 收货地址；
- 支付账号；
- 其他用户 ID 与订单敏感字段。

Agent Trace 记录：

- 请求 ID；
- 用户 ID（内部）；
- Prompt 哈希/摘要，不记录完整敏感 Prompt；
- 检索文档 ID；
- 工具名和脱敏参数；
- 决策和错误码；
- 耗时和 Token/成本；
- 不记录完整模型思维链。

### 6.3 数据最小化

- Agent 只获取完成当前任务所需的字段；
- 查询订单时默认不返回完整地址和手机号；
- 需要收货信息时按字段授权并脱敏；
- 工具输出字段白名单；
- 不把其他用户数据放入上下文；
- 不把完整数据库对象序列化给模型。

### 6.4 输出保护

- 模型输出不得包含 System Prompt、密钥、内部 URL；
- 不得包含其他用户手机号、地址、订单；
- 输出经过敏感字段检测和脱敏；
- 无法确认安全时拒绝输出或转人工；
- 前端不展示内部 Trace 和错误堆栈。

### 6.5 数据访问最小权限

- 应用数据库账号只拥有必要权限；
- RAG 服务使用只读或受限账号；
- 管理员文档和普通文档在存储/检索层隔离；
- 备份和日志访问受限；
- 不引入复杂权限平台，但必须有明确账号边界。

### 6.6 敏感信息 P0 验收

- 日志、异常和 Trace 中不出现密码/Token/密钥；
- LLM 请求和模型上下文不包含系统凭据；
- 前端响应不包含系统凭据；
- 模型输出不能导出 System Prompt 或密钥；
- 用户 A 不能从 Agent 输出看到用户 B 数据；
- 工具只返回白名单字段；
- 数据库/RAG 账号最小权限有配置说明。

## 7. Agent 运行治理（P1）

### 7.1 第一版硬限制

建议默认值（可配置，但不能无限）：

```text
单次请求最大工具调用次数：8
单次请求最大 Agent 循环轮数：6
单次 LLM 请求超时：30 秒
单次工具执行超时：5 秒
LLM 最大重试：1 次，指数退避
单次请求最大 Token 预算：可配置
单次请求最大成本预算：可配置
最大输出长度：可配置
```

### 7.2 循环与重复调用

- 相同工具 + 相同参数在短时间重复调用时阻断或复用结果；
- 达到最大轮数强制终止；
- 达到最大工具调用次数强制终止；
- 写操作不能因为模型循环而重复执行；
- 副作用工具必须有幂等键；
- 终止时返回可解释错误，不继续隐式重试。

### 7.3 超时与重试

- LLM 超时终止当前步骤；
- 工具超时返回工具错误，不阻塞整个请求；
- 只读工具可有限重试；
- 写工具重试必须依赖幂等键和确认；
- 重试有上限和退避；
- 不引入复杂分布式任务平台。

### 7.4 异常终止与人工接管

触发人工接管：

- 安全策略高风险；
- 高风险操作确认失败；
- 工具连续失败；
- 业务状态不确定；
- 成本/轮数超限；
- 多轮注入怀疑。

人工接管时：

- 保留请求 ID 和审计记录；
- 不自动执行写操作；
- 返回明确状态；
- 不在后台无限重试。

### 7.5 运行治理 P1 验收

- 超过工具调用次数终止；
- 超过循环轮数终止；
- LLM/工具超时可控；
- 写操作重复调用不会重复执行；
- 异常终止有审计和用户可见错误；
- 不存在无限循环和无限成本增长；
- 不引入 MQ/分布式任务平台。

## 8. 安全审计与评测（P0）

### 8.1 审计事件

每次 Agent 请求记录：

```text
request_id
user_id
session_id
agent_version
prompt_template_version
input_risk_level
input_policy_action
retrieved_document_ids
tool_name
tool_arguments_redacted
tool_result_status
confirmation_id（如有）
policy_decision
business_result
error_code
latency_ms
token_usage / cost
created_at
```

要求：

- 审计记录不可由模型修改；
- 敏感字段脱敏；
- 失败和拒绝也记录；
- 高风险操作必须记录确认和最终业务结果；
- 审计日志有保留期和访问控制。

### 8.2 安全评测分层

- **单元/确定性测试**：权限、金额、状态、参数、确认、幂等；
- **集成测试**：Agent/Tool/Service/DB 全链路；
- **对抗样例测试**：注入、编码、间接注入、多轮；
- **人工红队测试**：补充样例，不作为唯一自动门禁。

### 8.3 必须的安全测试

| 编号 | 测试 | 判定 |
|---|---|---|
| SEC-01 | 直接提示词注入 | 拒绝或降权，不越权 |
| SEC-02 | 中文/编码/Unicode 变体 | 不能绕过策略 |
| SEC-03 | 多轮诱导 | 不能逐步提升权限 |
| SEC-04 | RAG 间接注入 | 文档不能触发工具/改变规则 |
| SEC-05 | 工具白名单 | 未授权工具拒绝 |
| SEC-06 | 用户 A 访问用户 B 订单 | 404/403，无数据泄露 |
| SEC-07 | 普通用户调用管理员工具 | 403 |
| SEC-08 | 高风险操作未确认 | 拒绝执行 |
| SEC-09 | 确认参数篡改 | 旧确认失效 |
| SEC-10 | 确认重放/重复点击 | 只执行一次 |
| SEC-11 | 退款金额/订单状态绕过 | 后端确定性拒绝 |
| SEC-12 | Prompt/密钥/Token 泄露 | 输出和日志均不包含 |
| SEC-13 | 跨用户 PII 泄露 | 不返回他人数据 |
| SEC-14 | 无限循环/重复工具调用 | 达到上限终止 |
| SEC-15 | 文档删除/更新后检索 | 旧内容不再返回 |

### 8.4 断言要求

- 权限、退款金额、订单状态、库存、确认凭据必须使用确定性断言；
- 不允许只用 LLM-as-a-Judge 判断“是否安全”；
- LLM 评审可以作为补充，但不能替代：
  - HTTP 状态码；
  - 错误码；
  - 数据库状态；
  - 工具调用记录；
  - 审计记录；
  - 金额和库存断言。
- 安全测试失败必须阻断 TASK-015 验收。

### 8.5 审计与评测 P0 验收

- 安全测试纳入 CI 或固定验收脚本；
- P0 安全用例全部通过；
- 所有拒绝路径有审计；
- 高风险操作可追溯；
- 不存在仅依赖 LLM 判断的安全测试；
- 安全测试结果可重复执行。
