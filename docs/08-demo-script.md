# 08 现场演示脚本

## 1. 演示目标

让面试官在 8–10 分钟内看到：

```text
消费者商城
AI 导购
立即购买
我的订单
管理员履约
售后换货
运营后台
```

## 2. 演示前准备

### 启动服务

```text
MySQL 3307
Redis 6380
Qdrant 6333
后端 8000
前端 5173
```

### 三个浏览器标签页

```text
标签页 A：登录管理员
标签页 B：登录普通用户
标签页 C：登录调试人员
```

原因：当前 Token 在 `sessionStorage`，每个标签页独立存储，三个身份可以同时存在。关闭标签页后需要重新登录。

### 建议账号

```text
管理员：本地管理员账号
普通用户：本地注册的普通用户
```

不要把真实密码写进 README 或演示文档。

## 3. 演示流程

### 第 1 步：商城

打开：

```text
http://127.0.0.1:5173/shop
```

讲解：

- 10 个商品；
- 商品图片；
- 分类；
- 搜索；
- 库存；
- 价格。

### 第 2 步：商品详情

打开 P001：

```text
/shop/products/P001
```

讲解：

- SKU；
- 库存；
- 价格；
- 立即购买；
- 问 AI 导购。

### 第 3 步：AI 导购

打开：

```text
/shop/assistant
```

可以问：

```text
推荐一款手机
这款还有库存吗？
换货需要什么条件？
查询我的订单
```

讲解：

- LangGraph；
- READ Tool；
- RAG；
- 订单查询；
- 取消/换货 Prepare。

### 第 4 步：普通用户下单

在商品详情点击立即购买：

```text
收货人
手机号
地址
数量
```

提交后进入：

```text
/shop/orders
```

讲解：

- 创建 `CREATED` 订单；
- 库存预占；
- 没有支付；
- 管理员负责履约。

### 第 5 步：管理员履约

普通窗口登录管理员：

```text
http://127.0.0.1:5173/dashboard
```

打开订单管理，找到普通用户订单：

```text
发货 → 填写承运商/运单号
标记送达
```

讲解：

- 订单状态和履约状态分离；
- 发货扣减库存；
- 用户送达后才能申请售后。

### 第 6 步：普通用户申请换货

标签页 B 登录普通用户，打开订单详情：

```text
/shop/orders/{orderNo}
```

点击「申请换货」，填写原因，提交。

打开：

```text
/shop/after-sales
```

讲解：

- 售后类型只支持 EXCHANGE；
- 状态 `PENDING_REVIEW`。

### 第 7 步：管理员审核

管理员打开：

```text
/after-sales/{afterSalesNo}
```

点击审核通过：

```text
PENDING_REVIEW → WAITING_RETURN
```

### 第 8 步：用户寄回

普通用户打开售后详情：

```text
填写退货承运商和退货单号
```

状态变为：

```text
RETURN_SHIPPED
```

### 第 9 步：管理员收货、完成换货

管理员：

```text
确认收货 → RECEIVED
完成换货补发 → COMPLETED
```

普通用户刷新售后详情，看到完成。

## 4. 备用演示

如果某条数据不适合现场，可以只演示：

```text
商城浏览
商品详情
AI 导购
我的订单
管理员订单操作
售后页面
```

不要为了演示临时改业务状态。

## 5. 面试讲解重点

- 为什么 READ/PREPARE 分开；
- 为什么 Confirm 独立；
- 为什么 MySQL 是 RAG 权威源；
- 为什么订单和履约状态分开；
- 为什么没有支付/购物车；
- 当前哪些是 MVP，哪些是生产化待办。

## 6. 现场注意事项

```text
提前登录两个窗口
提前确认数据库/Redis/Qdrant 正常
不要把管理员和普通用户放在同一个标签页
不要关闭演示标签页，否则需要重新登录
不要现场删除数据
不要声称未实现的功能已经完成
```
