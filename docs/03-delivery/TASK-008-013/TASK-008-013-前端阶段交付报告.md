## 3. 页面功能

### TASK-009 认证和框架

- `/login`、`/register`；
- 登录成功后调用 `/auth/me` 建立用户状态；
- 未登录访问受保护页面跳转 `/login`；
- 401 使用共享 Refresh Promise 协调并发刷新，原请求最多重试一次；
- 刷新失败清除 Token 并跳转登录；
- 登出调用真实 `/auth/logout` 后清理本地 Token；
- 左侧导航、顶部用户信息、面包屑、页面容器。

### TASK-010 商品和库存

- 商品列表：编号、名称、分类、状态、创建时间；
- 商品搜索、状态筛选、分类筛选、分页；
- 新增商品；
- 商品详情、商品资料 PATCH；
- 商品上架/下架/归档；
- SKU 动态属性、价格、状态、库存；
- 新增 SKU、编辑 SKU 价格和状态；

- 订单详情：金额、支付/履约状态、明细、收货和物流信息；
- 售后列表：状态、类型、金额、原因；

- 真实 `/knowledge/retrieve` 检索测试；
- 明确提示“上传成功不代表索引完成”。

### TASK-013 Agent

- `/agent` 当前会话和新建会话；
- Enter 发送、Shift + Enter 换行、防重复提交；
- 普通回答、RAG sources、Pending Action；
- Pending Action 展示操作类型、业务编号、影响、摘要、过期时间；
- 确认前二次弹窗；
- 确认按钮 Loading，防止重复点击；
- Confirm 严格提交：

```json
{
  "conversation_id": "uuid",
  "nonce": "opaque-nonce"
}
```

- 不提交订单号、SKU、金额、售后类型等业务参数；
- 未收到后端成功响应前不显示成功；
- 后端 503/409/404 等错误使用中文提示；
- 放弃操作只清除前端卡片，不声称后端凭证已撤销。

## 5. 认证和安全

- Token 存储于 `localStorage`：
  - `ecommerce_agent_access_token`
  - `ecommerce_agent_refresh_token`
- 这是后端 JSON Token 机制下的实现选择；
- 风险：XSS 可读取 Token。前端未使用 `dangerouslySetInnerHTML`，Agent 输出按文本渲染；
- Refresh Token Rotation 通过模块级共享 Promise 协调，避免并发请求重复刷新；
- API Base URL 默认使用同源 `/api/v1`，开发由 Vite 代理，生产应由 Nginx 同源代理；
- 后端当前未配置 CORS middleware，因此不应把开发环境改成跨域绝对地址；
- 前端不保存 DeepSeek Key、数据库/Redis 密码、JWT Secret 或支付私钥；
- `GET /auth/me` 只返回 `id/email/is_active`，没有 `is_admin`；前端不伪造管理员角色，最终权限由后端 403 保证。

## 7. 设计与真实接口差异记录

| 设计 | 真实接口 | 处理 |
|---|---|---|
| `/products/:productNo` | 管理端按 `product_id` 查询 | 使用 `/products/:productId`，页面展示 `product_no` |
| `/inventory` 直接列表 | 只有 `/admin/inventory/{sku_id}` | 通过商品 → SKU 钻取 |
| 订单编号搜索 | 管理端订单列表没有 `keyword` 参数 | 当前页前端过滤 |
| 售后编号/订单搜索 | 管理端售后列表只有 `status` | 当前页前端编号过滤 |
| 订单详情支付信息 | PaymentResponse 没有 `order_no` | 只展示订单权威支付状态，不伪造支付单关联 |
| 管理员菜单 | `/auth/me` 没有 `is_admin` | 不伪造角色；403 由后端和页面提示 |
| API Base URL 可用绝对地址 | 后端没有 CORS middleware | 默认同源 `/api/v1` + Vite/Nginx 代理 |
